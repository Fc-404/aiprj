# aiproj.code.md

**AI 工程文件体系模板 — 让 AI 快速理解、定位、开展代码项目。**

---

## 这是什么？

一份 markdown 指南，定义了 `aiprj/` 工程文件目录的结构和使用规范。AI 拿到这个模板后，按照指引为你的项目创建一套工程文档，让 AI 能快速理解项目全貌、避免反复踩坑、记录每次纠正。

## 快速使用

```bash
# 克隆本仓库
git clone https://github.com/Fc-404/aiprj.git

# 把模板复制到你的项目根目录
cp aiprj/aiprj.code.md 你的项目根目录/

# 告诉 AI："按 aiprj.code.md 的指引，为项目创建工程文件"
```

AI 会阅读 `aiprj.code.md`，然后：
1. 通过对话了解你的项目
2. 创建 `aiprj/` 目录及对应工程文档
3. 后续每次对话自动维护这些文件

## 文件结构

```
aiprj/                   ← AI 创建，放在你的项目根目录
├── README.md            [必建] 项目入口 + 约束 + 文件索引
├── 01-ARCHITECTURE.md   [必建] 系统架构
├── 02-TECH-STACK.md     [可选] 技术栈
├── 03-API-DESIGN.md     [可选] API 接口
├── 04-DATABASE.md       [可选] 数据库
├── 05-PROTOCOL.md       [可选] 通信协议
├── 06-DIRECTORY.md      [必建] 目录结构
├── 07-DEVELOPMENT.md    [可选] 开发指南
├── 08-REFERENCES.md     [可选] 参考术语
└── 09-CHANGELOG.md      [必建] 修正记录 ⭐
```

## 核心理念

| 理念 | 说明 |
|------|------|
| **写给 AI 看** | 工程文档的主要读者是 AI，不是人 |
| **动态适配** | 根据项目规模决定建哪些文件，不强制全量 |
| **修正必记** | 用户每次纠正都记入 CHANGELOG，AI 不会再犯 |
| **AI 自主 + 用户确认** | AI 判断文件结构，调整前先问用户 |

## 适用场景

- 需要用 AI 辅助开发代码项目
- 项目有一定复杂度，AI 频繁进入/退出需要恢复上下文
- 多个 AI 代理协作同一个项目
- 希望 AI 记住用户的纠正和偏好
